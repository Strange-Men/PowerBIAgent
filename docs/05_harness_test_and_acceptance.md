## 一、Harness 设计

### 1.1 目标

MVP Harness 用于限制 Agent 行为、防止开发偏移，并持续验证数据结果。

采用适合 MVP 的轻量控制面，不引入复杂编排框架。

### 1.2 控制面组成

#### 结构化输出约束

LLM 的关键输出必须符合固定 Pydantic 结构：
- IntentSpec
- QueryPlan
- DAX
- AnswerSpec
- ReportSpec

#### 工具白名单

Agent 只能调用以下工具：
- `get_semantic_model_schema`
- `execute_dax`
- `render_report`

#### 查询限制

- 查询超时时间
- 最大返回行数
- 最大重试次数
- 禁止危险或无关查询
- 禁止访问未选择的语义模型

#### Trace

每次请求记录完整链路：
- 用户问题
- 语义模型 / 模板
- 意图识别结果
- 查询计划
- 生成的 DAX
- MCP 返回数据摘要
- 最终答案 / ReportSpec
- 错误信息
- 各阶段耗时

## 二、Golden Cases

### 2.1 设计目标

建立约 20-30 个固定测试问题，每次修改 Prompt、Agent、MCP Adapter 或报表模块后执行回归测试。

### 2.2 覆盖场景

| 场景类别 | 示例 | 数量 |
|---------|------|------|
| 单指标查询 | "本月销售额是多少？" | ~3 |
| 区域排名 | "各区域销售额排名" | ~3 |
| 时间趋势 | "最近六个月趋势" | ~3 |
| 多条件筛选 | "华南区本月利润率" | ~3 |
| 连续追问 | 多轮对话场景 | ~3 |
| 空数据 | 查询无结果 | ~2 |
| 错误字段 | 输入不存在的指标 | ~2 |
| DAX 失败 | MCP 返回错误 | ~2 |
| 报表生成 | 销售周报/满意度报告 | ~4 |
